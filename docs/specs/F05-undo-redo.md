# F05 撤销与重做

- 状态：已实现
- 关联：[ADR 0004](../adr/0004-state-management-undo.md)、[ADR 0021](../adr/0021-edit-commit-module.md)

## 概述

为编辑操作提供有界的撤销与重做能力。

## 非目标

- 操作历史列表 UI、跨会话撤销（重启后撤销栈清空，文档本身由 F06 恢复）。

## 需求与场景

### 需求 1：基本撤销重做

#### Scenario: 撤销添加文本

- GIVEN 用户刚添加了一个文本块
- WHEN 用户点击撤销
- THEN 该文本块从画布消失
- AND 点击重做后文本块恢复

#### Scenario: 连续多步撤销

- GIVEN 用户依次执行了加字、调背景色、调间距三次提交
- WHEN 用户连续点击撤销三次
- THEN 文档逐步回退到三次操作之前的状态，顺序与操作相反

### 需求 2：提交粒度

#### Scenario: 滑杆调整只产生一个撤销步

- GIVEN 用户按住间距滑杆连续拖动（产生大量中间值）
- WHEN 用户松开滑杆后点击一次撤销
- THEN 间距恢复到本次拖动开始前的值（整个拖动是一个撤销步）

#### Scenario: 重复选择当前值不增加撤销步骤

- GIVEN 当前编辑结果已经使用目标设置值
- WHEN 用户再次提交相同的设置值
- THEN 撤销记录不增加新的步骤

### 需求 3：边界行为

#### Scenario: 没有可撤销操作时按钮不可用

- GIVEN 编辑会话刚开始，无任何提交
- WHEN 用户查看撤销操作
- THEN 撤销按钮处于禁用态

#### Scenario: 新提交清空重做分支

- GIVEN 用户撤销了两步
- WHEN 用户执行一次新的编辑提交
- THEN 重做按钮变为禁用态（被撤销的分支不可再重做）

#### Scenario: 撤销记录有上限

- GIVEN 用户连续执行的编辑次数已经超过撤销记录上限
- WHEN 用户连续撤销到不能再撤销
- THEN 应用停留在仍被保留的最早状态，且不会崩溃
