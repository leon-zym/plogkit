# ADR 0040：系统照片选择器以整批结果交付导入候选

- 状态：已接受
- 接受日期：2026-08-09
- 修订：[ADR 0006](0006-image-import-pipeline.md)
- 关联：[ADR 0022](0022-draft-aggregate-current-editing-session.md)、[F07](../specs/F07-image-import.md)

## 背景

Expo ImagePicker 在允许从网络获取资产时，可以等待系统准备仅存于 iCloud 的照片，但向应用暴露的是单个异步选择结果。这个边界不提供逐张下载进度、逐张错误详情或由应用控制的下载超时；系统完成准备前，PlogKit 尚未获得可供本地导入的候选照片。

ADR 0006 中“等待下载并由应用在超时后提示”的决策没有经过该接口能力验证，也混淆了系统照片选择阶段与应用本地导入阶段。

## 决策

- 系统照片选择器负责把本地照片和仅存于 iCloud 的照片作为一个批次进行选择与准备。
- PlogKit 等待选择结果期间只显示统一、无具体进度的准备中状态。
- 系统选择边界只向应用返回三种结果：整批候选照片、用户取消或整批错误。应用不虚构逐张进度、逐张错误或自有下载超时。
- 系统选择整批错误时不创建草稿，并向用户提供重新选择的提示。
- 系统成功交付候选照片后，应用才进入 ADR 0022 定义的本地导入阶段；本地导入继续按候选照片分别提交，允许保留成功照片并提示存在失败。
- 如果未来 Expo 提供结构化的逐张状态或进度，再通过新的 ADR 评估产品行为，不为当前不可观测状态增加测试专用接口或原生兼容层。

## 影响与代价

- 混合选择本地照片和 iCloud 照片时，系统准备失败需要用户重新选择整批照片，应用无法指出具体失败照片。
- 产品不再承诺底层接口无法提供的进度和超时语义，测试也只验证真实可观测边界。
- 系统成功返回后的本地复制、预览生成和逐项部分成功语义不受影响。
